# 首次发布计划

## 发布前

1. 用 5 到 10 份经过脱敏的 WizTree CSV 验证分类，修正误报。
2. 做一张真实界面截图和一段 30 到 60 秒演示：C 盘扫描 -> 分类 -> 分级方案 -> 报告。
3. 确定开源许可证、项目名、仓库描述，以及是否接受问题反馈。DiskPilot 已被多个公开仓库使用，正式发布前应检查名称是否足够独特。
4. 写清楚隐私边界、数据不出本机、当前不执行删除。

## GitHub 发布当天

1. 建立公开仓库，添加 README、截图、LICENSE、Issues 模板、Topics。
2. 发布带版本号的 Release，并给出可复现的运行方式。
3. 用具体案例写第一条介绍：例如一个 12 GB 的项目目录是如何被识别并给出审阅建议的。
4. 到相关 Windows、开发者和开源社区分享案例，尊重社区规则。

## 发布后四周

- 第 1 周：收集 10 个真实问题，优先修正误分类和使用障碍。
- 第 2 周：发布修复版，展示前后对比和已解决的问题。
- 第 3 周：加入英文 README、英文截图，扩大可发现范围。
- 第 4 周：整理下一阶段的 AI 与迁移需求，让用户投票。

目标先看真实使用、问题反馈和回访，再看 Stars。不要购买或交换 Stars。

## GitHub 连接状态

已确认账号连接成功，不需要提供密码或令牌。当前连接器可操作已有仓库；创建新仓库时可使用 GitHub 网页或另行安装 GitHub CLI。公开发布前仍需确认仓库名、许可证和发布范围。
